# Known Limitations and Unverified Requirements

0. **Overall:** software complete with physical validation pending (docs/reports/FINAL-COMPLETION-AUDIT.md). Hardware raw-frame TX (REQ-CAN-003) is BLOCKED: Rev B cannot transmit and CW1 v1 has no host-to-firmware TX command.
1. **Native Proteus file:** the generator writes OrCAD EDIF2 import sources (hardware sheet and a CAN Bus Analyser simulation bench) plus SVG, netlist, BOM and design checks. Their stored and drawn connectivity is verified offline. A real import in Proteus 9.2 SP1 on the owner's Windows PC (2026-10-25) parsed the file but exposed two generator defects (0 components, 26 missing connections); both are fixed, but the corrected files have not been re-imported, saved as .pdsprj or simulated. The simulation bench uses Labcenter's generic CAN_TRANSCEIVER model for the TJA1051 symbol (no TJA1051 model ships), so Silent mode is not simulated. See native-project-status.json.
2. **Transceiver variant:** the marking NXP TJA1051 25 06 ND312 is not decoded into an orderable type. Pin 5 is left open (fail-safe for every variant); Rev B receives only if pin 5 is n.c., which must be confirmed on the bench.
3. **Physical bench:** Rev B receive-only interface values are defined and checked on paper (design-checks.json). Header continuity, pin-1 orientation, Silent-bias and RXD levels, and bench behaviour are not yet measured. No firmware was flashed.
4. **CAN bus:** no vehicle bitrate/topology/safe tap point or identifier has been observed. No live capture or transmission on the Civic occurred.
5. **Host TX:** Rev B hardware cannot transmit (TXD not wired, S tied HIGH). repeat scheduling, cancellation and audit work end-to-end on the virtual bus. The host has no physical TX control path. The firmware offers a guarded single-frame C API, but the CW1 protocol is read-only and does not expose host commands for it.
6. **Diagnostic workflows:** capability evidence/gates are implemented as metadata and simulation-only eligibility evaluation. No Honda-specific ECU address/service or executable vehicle diagnostic is shipped.
7. **Browser validation:** static files/API are covered by tests; no full cross-browser visual certification or device accessibility audit was performed.
8. **Performance:** benchmark figures reflect a synthetic single-host run, not UART/CAN throughput, physical real-time latency or multi-user server capacity.
9. **Network security:** server is local-only and unauthenticated; do not expose it externally. Any future remote-access feature needs authentication, CSRF protections appropriate to that deployment and a new threat review.
10. **Firmware/serial:** the firmware emits monotonic observation/dequeue timestamps, not precise wire Start-of-Frame timestamps; the host bridge has not been tested on an actual hardware port.
11. **Independent validation:** when the operator promotes a mapping, the application records the supplied method and references. The software cannot independently verify the truth of external evidence.
